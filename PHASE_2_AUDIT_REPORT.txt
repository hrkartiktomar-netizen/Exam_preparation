FEATURE BREAKDOWN
================================================================================

1. DAILY POLLING (Autonomous)
   • CronTrigger scheduled at 3am UTC daily
   • Sources: IFSCA, RBI, ICSI (URLs configurable)
   • Polling interval: Daily
   • HTML parsing: BeautifulSoup4
   • Error handling: Graceful skip + logging per FALLBACK_DECISION tree

2. DEDUPLICATION (SHA256)
   • Content-based deduplication prevents replay attacks
   • UNIQUE constraint on sha256 field enforces invariant
   • amendment_extraction_cache table stores hash + source + status
   • Cost control: Ensures we don't re-process same circular twice

3. GEMINI EXTRACTION
   • extract_and_verify_amendment(text, url) returns structured amendment
   • Fields extracted: topic, rule_name, old_value, new_value, effective_date, priority
   • Fallback: LOCAL_FALLBACK mode if Gemini unavailable (marks for manual review)
   • Gemini model: Default gemini-flash-latest with temperature=0.1 (deterministic)

4. AUTO-QUESTION GENERATION
   • Job Queue: SQLite-based, single-user, no distributed overhead
   • For each amendment: _queue_questions() enqueues 3 jobs
   • Job type: amendment_questions
   • Executor: execute_amendment_questions() generates Qs via db.generate_amendment_questions()
   • Retry logic: Auto-retry up to max_retries on failure

5. AMENDMENT RADAR DASHBOARD
   • API endpoint: GET /api/amendments/status
   • Returns: new_count_this_week, last_poll_at, amendments list
   • Frontend: loadAmendmentRadar() fetches + displays
   • Widget: Shows new amendments with priority coloring
   • Integration: Called from loadDashboard() on page load

================================================================================
RISK MITIGATION
================================================================================

1. Gemini Rate Limiting (429 errors)
   → Exponential backoff: 500ms → 1s → 2s (per FALLBACK_DECISION tree)
   → Retry max 3 times then fallback to LOCAL mode

2. Database Lock (concurrent access)
   → PRAGMA busy_timeout=30000ms mitigates database locks
   → Single-user app, but still defensive

3. Malformed HTML from polling sources
   → try/except around BeautifulSoup parsing
   → Graceful skip + log warning if parse fails
   → Continue with next source

4. Gemini Extraction Failure
   → Fallback: LOCAL_FALLBACK mode marks amendment for manual review
   → Tagging: verify_status = GEMINI_EXTRACTED vs LOCAL_FALLBACK

5. Job Queue Failure
   → Automatic retry mechanism (configurable max_retries)
   → After max retries exceeded: mark job as FAILED + log error
   → User can view job history + debug
